## (1)AndroidAppフォルダ
  Flutterを利用し、作成したAndroidアプリに関連するものを含むフォルダである。アプリの内容を簡単に説明すると、スマホで取得した歩数をもとにゲーム内のポイントに変換し、グラフ上のマスを取り合う陣取り取りゲームである。大学院の講義で社会課題を意識し、企画から実機での実装まで5人のチームで作成したものである<br>

　　である。<br>
　・全年代のユーザーが親しめるようにゲームコンセプトを全年代が親しめる野菜にしたこと<br>
　である。

## (5)Insightフォルダ
  フロントエンドをReact + TypeScript + Vite、バックエンドをGO,Djangoを使い大学院の講義で5人のチームで作成したwebアプリである。この講義は講義の参加者がそれぞれアプリを提案し、投票で選ばれたものを作るというもので、本アプリは自身が企画したものが投票で選ばれ、リーダとして開発を務めた。<br>
  アプリの内容を簡単に説明すると、漫画やアニメなどの様々なジャンルのコンテンツの考察や感想をネタバレを気にせず投稿・閲覧できるSNSアプリである。タイムラインはコンテンツごとに用意されている。また各投稿にはタイトルや何話に対する投稿か、その投稿者は投稿時点で何話まで読んでいたかが紐づけられており、自身の読んでいる話数より先の投稿がタイムラインに表示されないようになっている。例えば漫画Aを300話まで読んでいる人の漫画Aのタイムラインには投稿した時点で漫画Aを300話までしか読んでいない人の投稿のみが表示されるようになっている。<br>
  私の担当はフロントエンドのタイムライン画面や話数選択画面、プロフィール画面の作成である。タイムライン画面では投稿の検索、並び替え、いいねや投稿、返信といった基本的なSNS機能を実装している。話数選択画面ではタイムラインに表示したい投稿の話数を選択できるようになっている。ここで自身が読んでいる話数より先の話数を選択すると、確認画面が現れ、その漫画に対する自身の読んでいる話数を更新するようになっている。プロフィール画面については、ユーザーがどのコンテンツをどこまで読んだり、見たりしているかがわかるようになっており、ユーザーの名前やアイコンの編集を行えるようにもなっている。また。投稿をサーバーから取得するようにも連携した。<br>
  作成に当たってこだわった点、注意した点としては<br>
　・マンガなどの考察のネタバレが起きるあらゆる場面を考え、ネタバレが一切起きないような仕組みを考えたこと<br>
　・ユーザーが求めている機能を話し合いながら必要な機能は全て実装したこと<br>
　・普段考察を行わない層も気軽に利用できるように、カラーは緑系統としたことや話数選択と同時に自動で何話まで読んだかが変わるようにするなどのユーザーの負担を極力減らすようなデザインを考えたこと<br>
　・リーダーとして、メンバーの意見を多く取り入れ、全員が納得するようなものにしたこと<br>
